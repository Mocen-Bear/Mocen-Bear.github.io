嘉立创实战派 ESP32-S3 和普通「最小系统板」不太一样：板载 320×240 的屏、电容触摸、音频编解码芯片，还有一颗 IO 扩展芯片，基本上拿到手就能当一个小型触屏设备用。

这篇文章讲两件事：怎么改它的固件，怎么把改完的固件烧进去跑起来。

## 先认识这块板子

板子全名是嘉立创·实战派 ESP32-S3。核心是 ESP32-S3 芯片（双核，带 WiFi 和蓝牙），外围配置大概是这些：

| 部件 | 型号/参数 | 作用 |
|---|---|---|
| 主控 | ESP32-S3 | 跑逻辑、连 WiFi |
| 屏幕 | ST7789，320×240 | SPI 接口，走 esp_lcd |
| 触摸 | FT6336（I2C 地址 0x38） | 电容触摸 |
| 音频 | ES8311 + 板载功放 | 录音和放音 |
| IO 扩展 | PCA9557（0x19） | 屏幕 CS 等引脚挂在它上面 |

它和我之前用的 Arduino UNO 完全是两个量级的东西，思维上要切换一下：

| | Arduino UNO | 实战派 ESP32-S3 |
|---|---|---|
| 主频 | 16MHz | 240MHz，双核 |
| 网络 | 没有 | WiFi + 蓝牙自带 |
| 存储 | 32KB | 16MB Flash（可跑大程序） |
| 开发方式 | 一样是 Arduino 框架 | 一样，但工具链和参数不同 |

## 装开发环境

两种方式，选一种就行。

**方式一：Arduino IDE（适合点点点）**

1. 装 Arduino IDE 2.x；
2. 首选项里「附加开发板管理器网址」填：
   `https://espressif.github.io/arduino-esp32/package_esp32_index.json`
3. 开发板管理器搜 `esp32`，装 espressif 的包（3.x 版本）；
4. 开发板选「ESP32S3 Dev Module」，Flash Size 选 16MB。

**方式二：命令行（适合反复编译、脚本化）**

我后来一直用命令行，因为编译参数可以固定下来，不用每次点菜单：

```bash
arduino-cli core install esp32:esp32
arduino-cli board list          # 看板子接在哪个串口
```

## 编译和烧录

实战派这块板子要指定 Flash 大小和分区方案，不然编出来能过、跑起来会出问题（程序区不够大、文件系统起不来）：

```bash
# 编译：注意 fqbn 里这三个参数
arduino-cli compile --fqbn esp32:esp32:esp32s3:FlashSize=16M,PartitionScheme=huge_app .

# 烧录：-p 后面是板子的串口号
arduino-cli upload -p COM7 --fqbn esp32:esp32:esp32s3:FlashSize=16M,PartitionScheme=huge_app .
```

`huge_app` 的意思是给程序区尽量大的空间，代价是文件系统小。带屏幕和音频的项目程序都不小，选它比较稳。

## 这块板子有两个串口，别搞混

这是我一开始最懵的地方：插上 USB 之后电脑里冒出两个串口。

- **一个走 ESP32-S3 原生 USB**：用来烧录，速度稳；
- **一个走 CH340 转串口芯片**：用来接串口监视器看日志。

所以实际用法是：烧录用原生口，日志盯着另一个口（115200 波特率）。写代码的时候在开头把日志打到 `Serial`，然后开着监视器，程序跑到哪一步、有没有连上 WiFi，全靠它。

```bash
# 看日志（端口号按你电脑实际显示改）
arduino-cli monitor -p COM8 -c baudrate=115200
```

## 改固件的几个实际操作建议

**把要改的东西集中到文件头。** 引脚号、服务地址、时长阈值这类参数，全部写成文件最上面的常量：

```cpp
/* ===== 配置区：改这里就行 ===== */
const int PIN_BL      = 42;          // 背光，低电平点亮
const int TOUCH_ADDR  = 0x38;        // FT6336
const char* SERVER_HOST = "192.168.1.100";  // 换成你自己的服务地址
const int MAX_RECORD_MS = 60000;     // 录音最长 60 秒
```

这样下次改行为不用在几百行里翻，改常量 → 编译 → 烧录，三步走完。

**先用厂家例程点亮屏幕。** 屏幕初始化是这个板子最容易翻车的地方：SPI 模式、颜色反相、XY 交换、镜像方向、CS 挂在 IO 扩展芯片上要先拉低……少一样就是白屏或者花屏。我最后是直接照抄立创官方例程 `esp32_s3_szp.c` 里 esp_lcd 的初始化路径，一个参数都不改，先点亮，再往上加自己的逻辑。**换库、换封装之前，先把厂家例程跑通**，这条经验省了我至少两天。

**加一个能看见的状态灯。** 屏幕上角画个小圆点：绿=网络和服务都通，橙=WiFi 通了但服务连不上，红=离线。没有它的时候，程序挂了只能靠猜。

## 常见问题

| 现象 | 大概率原因 | 怎么办 |
|---|---|---|
| 设备管理器里找不到串口 | 用的是充电线，或者没装 CH340 驱动 | 换数据线；装 CH340 驱动 |
| 上传报 Failed to connect | 板子没进下载模式 | 按住 BOOT 键，点一下 RST，再松手重新上传 |
| 串口监视器全是乱码 | 波特率不对 | 改成 115200 |
| 屏幕白屏/花屏 | 初始化参数或 CS 控制不对 | 回退到厂家例程，参数一个别改 |
| 改了代码但现象没变 | 没重新上传，或者传到了错误的串口 | 确认编译产物时间、确认 `-p` 端口 |
| 程序跑一会就重启 | 内存不够或看门狗触发 | 看日志里的重启原因，减小缓冲区 |

## 最后

这块板子的门槛不在写代码，在**第一次把环境、串口、屏幕初始化这三样弄对**。弄对之后它就是一块带屏带网的普通单片机，改逻辑、加功能都是常规操作。

我自己的习惯是：配置集中到文件头、日志常开、状态可视化。做到这三条，后面改多少版都不慌。

> 提醒一句：固件里如果写了 WiFi 密码之类的敏感信息，提交到公开仓库前记得换成占位符，真实密码只留在你自己本地的编译副本里。
