涂鸦 T5AI-Board 是一块为 AI 语音场景做的开发板：板子和 LCD 屏叠在一起，带触摸、麦克风、喇叭和 WiFi。和常见的 ESP32 板不同，它有自己的一套板包和授权体系，第一次上手容易被几个细节卡住。

这篇把编辑固件、编译烧录，以及容易踩的坑记下来。

## 板子的基本情况

| 部件 | 说明 |
|---|---|
| 主控 | 涂鸦 T5 系列模组（WiFi + 蓝牙） |
| 屏幕 | ILI9488，原生 320×480 竖屏，RGB 接口 |
| 触摸 | 电容触摸，坐标要跟屏幕旋转一起补偿 |
| 音频 | 板载麦克风 + 喇叭，走涂鸦的 Audio 库 |
| 开发框架 | Arduino 语法，但板包是涂鸦自己的 `tuya_open` |

它和嘉立创实战派那种「纯 ESP32 + 外设」的板子区别在于：**它多了一层涂鸦 SDK 和云服务授权**。只做本地功能可以绕过这层；要接涂鸦云（语音识别、TTS）就必须配授权。

## 装板包

官方文档在 tuyaopen.ai，按「develop-with-Arduino」那一页操作，大致步骤：

1. 装 Arduino IDE 2.x；
2. 首选项里添加涂鸦的板包索引地址；
3. 开发板管理器搜 `TUYA_T5AI`，装 `arduino-TuyaOpen` 板包。

装完开发板列表里会出现 **TUYA_T5AI_BOARD**。命令行的板子标识是：

```
tuya_open:tuya_open:TUYA_T5AI_BOARD
```

## 编译和烧录

```bash
# 编译
arduino-cli compile --fqbn tuya_open:tuya_open:TUYA_T5AI_BOARD .

# 烧录：-p 后面是板子串口
arduino-cli upload -p COM9 --fqbn tuya_open:tuya_open:TUYA_T5AI_BOARD .
```

看到 `[INFO] Flash write success` 就是成功。

## 两个 USB 口，只认一个

这块板子用了 CH342 双串口芯片，插上去电脑里会出现两个 COM 口。实际使用：

- **A 口**：烧录走这里，串口日志也从这里看；
- **B 口**：不要用来烧录，日志也是乱码。

所以串口监视器里全是乱码时，先确认是不是接错口了，别急着改波特率。

## 授权三件套是什么

涂鸦云相关功能需要三个值：

```cpp
#define TUYA_DEVICE_UUID    "uuidxxxxxxxxxxxxxxxx"   // 涂鸦平台申请
#define TUYA_DEVICE_AUTHKEY "keyxxxxxxxxxxxxxxxx"    // 涂鸦平台申请
#define TUYA_PRODUCT_ID     "xxxxxxxxxxxxxxxx"       // 建产品后得到 PID
```

**实测结论**：这三个值填占位符，SDK 照样正常启动，本地功能（屏幕、按钮、录音、HTTP 请求）都不受影响。只有真正调用云端 ASR/TTS 时才会因授权失败报错。本地调试阶段不用急着找授权码。

## 中文显示：位图方案

LVGL 默认字体不含汉字，离线环境又装不了字体转换器，这是最烦的一点。解决办法是用脚本把要显示的字（「我没事」「听留言」「我到了」之类）**预先渲染成位图数组**，生成一个头文件，代码里当图片贴上去。

```python
# 生成脚本大致逻辑：每个汉字 -> 一张 lv_img_dsc_t
# 输出 t5ai_bitmaps.h，代码里 lv_img_create + lv_img_set_src 引用
```

好处是单源生成：改按钮文字就重跑脚本，不用手改一堆十六进制数组。缺点也明显——**字库是死的**，新增文字必须重新生成。

## 屏幕旋转和触摸补偿

面板原生竖屏（320×480），但界面要横着用。板级有个旋转宏：

```cpp
#define BOARD_LCD_ROTATION 0    // 控制底层旋转
```

界面层再旋转 90 度跑横屏，触摸坐标的补偿交给 LVGL 的 indev 层。这里要注意：**旋转、镜像、坐标补偿是一套的**，只改一半就会出现「点左边跳到右边」。建议先用官方例程确认触摸方向正确，再往上搭界面。

## 必须避开的坑：别在 LVGL 回调里做同步 HTTP

最早那版是：按下按钮 → 回调里直接发 HTTP → 等返回 → 更新界面。结果服务端稍慢，整个 UI 就卡住，连触摸都没反应。

正确做法是**异步**：

```cpp
// 回调里只做两件事：给界面反馈、记下待发请求
static void btn_cb(lv_event_t *e) {
    show_feedback("发送中...");
    g_pending = 1;          // 挂个标记，立即返回
}

// 真正发请求放到 loop 里
void loop() {
    if (g_pending) {
        g_pending = 0;
        send_request();     // 别在 LVGL 回调线程里阻塞
    }
    lv_timer_handler();
}
```

LVGL 走的是 UI 线程，任何阻塞操作都会让界面假死。这条在任何带屏项目里都通用。

## 录音规格：和其他板子一致

用涂鸦 Audio 库录出来是 **16kHz / 16bit / 单声道 PCM**，和其他板子上的录音格式完全一样，所以可以直接把二进制流 POST 给后端做关键词识别，后端不用区分是哪块板子录的。

```cpp
// 录 3 秒，拿到 PCM 直接 POST；不要自己加 WAV 头，后端统一处理
POST /voice_cmd
Content-Type: application/octet-stream
```

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 编译报找不到 `tuya_open` 板包 | 板包没装或索引没加 | 重装 arduino-TuyaOpen |
| 上传失败 | 接错串口（用了 B 口） | 换 A 口 |
| 串口日志乱码 | 同上，或波特率不对 | 确认 A 口，115200 |
| 屏幕白屏/花屏 | 旋转宏或 LCD 初始化不对 | 回退官方例程，先点亮再改 |
| 触摸点不准 | 旋转和坐标补偿没配套改 | 先跑官方例程校准方向 |
| 云端语音报错 | 授权码是占位符 | 本地调试可忽略；要上云再申请 |

## 最后

涂鸦这块板子的定位很明确：**把「语音交互 + 带屏界面」的底层都铺好了**。上手成本主要在板包安装、双串口识别、屏幕旋转这三件事上，过了这三关，剩下的和普通 Arduino 项目差别不大。

如果只做本地演示，完全可以不碰涂鸦云，把它当成一块带屏带麦带喇叭的 ESP32 来用，反而更省心。
